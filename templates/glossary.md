# Glossary

Read this before writing to the owner, a proposal or a document. It is the
one list of <project>'s official terms. A term means exactly what its line
says; the code name column is where it lives today. Agents keep this list:
they add, rename and drop terms themselves and tell the owner afterwards.

## Rules

1. **Use the official term, never a synonym.** When the owner, a document
   and the code use different words for one thing, the term below wins in
   prose; code keeps its name until a task renames it.
2. **Backticks in replies to the owner.** Every official term in a reply is
   wrapped in backticks.
3. **Agents own the vocabulary.** Add, rename or drop a term without asking
   when a concept came up twice without a name, two words are used for one
   thing, one word is used for two things, or the owner coins a term. Write
   the meaning in one line, where it lives, and the date. A term that
   exists only in an undecided proposal gets `pending: <path>` as its code
   name. A rename or drop updates the prose that uses the term in the same
   change, or records the sweep still owed.
4. **Tell the owner afterwards.** Name every term added, renamed or dropped
   in the next report ("New terms: `Wishlist`"). The owner changes it then
   if they dislike it; no approval step.
5. **Dropped terms stay listed** so nobody brings them back.
