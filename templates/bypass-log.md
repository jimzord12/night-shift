# Bypass log

Read this before planning work on shared code, and add to it whenever you
go around a shared component, template or contract to deliver what the
owner wanted. A bypass goes around components, never around the project's
non-negotiable rules. Newest at the bottom. Never delete an entry; mark it
closed when the gap is filled.

Each entry is a few lines:

```text
### YYYY-MM-DD  short title                     Status: open [, where it is planned] | closed by <commit, card or decision>
Needed:   what the owner or the product required
Bypassed: which component, template or contract could not do it
Built:    what was done instead, and where
Lesson:   what the shared code would need, in one sentence
```

A gap that appears a second time is flagged for shared-code work; a third
appearance makes it a card (rule of three).
